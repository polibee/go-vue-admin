# Resource CRUD 完整能力设计

## 目标

补齐通用后台面板的资源 CRUD 能力，先解决审计日志手动清理的可验证性，再统一批量选择、批量 Action、Manifest 筛选器，最后加入软删除和表格视图能力。

## 统一边界

- 所有资源操作都经过 Resource Manifest、权限、数据范围和字段权限校验。
- 批量请求支持 `ids` 和 `query` 两种选择模式；`query` 表示当前筛选条件，不接受前端伪造的总数量。
- 批量结果统一返回成功、失败、跳过及原因。
- 审计清理是审计域维护操作，不作为普通 Resource 批量删除复用。
- Manifest 显式声明筛选器，不再由字段类型隐式推断。
- 默认不启用导入；导出继续作为可选资源能力。

## 分阶段验收

1. 审计清理：有权限时按钮、接口和删除结果一致；无权限返回 403；操作写入审计；保留天数边界有测试。
2. 批量选择：当前页选择、跨页保留选择、按当前筛选条件全选和排除项都能正确表达，并在后端重新解析查询。
3. 批量操作：删除、字段更新和 Manifest 自定义 Action 共用契约，逐项返回结果并执行完整授权检查。
4. 筛选器：select、multi-select、boolean、text、date range、relation option 可由 Manifest 声明，后端校验查询参数。
5. 软删除与视图：资源可声明软删除；列表支持回收站、恢复、永久删除；用户可保存和恢复列、排序、筛选视图。

## 非目标

- 不引入 Filament 依赖或复制其实现。
- 不在本阶段加入请求/响应审计脱敏以外的新审计字段。
- 不改变 PostgreSQL、Redis 和 Laragon 的用户管理方式。
