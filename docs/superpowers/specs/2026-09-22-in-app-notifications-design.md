# 站内通知设计

## 目标

为通用后台面板提供第一版站内通知能力。通知必须复用现有认证、权限、PostgreSQL 和模块化目录约定，让业务模块通过统一服务发布通知，用户只能读取自己的通知。

## 范围

本阶段只实现站内通知：持久化、未读数量、列表、标记单条已读、全部标记已读和业务跳转。暂不实现邮件、短信、WebSocket、插件通知渠道、文件上传或导入。

## 后端设计

新增 `backend/app/services/notifications/`，由通知服务负责创建、查询和状态更新；业务模块不得直接写通知表。

新增 PostgreSQL 通知表，核心字段为：

- `id`
- `user_id`
- `type`
- `title`
- `body`
- `url`（可空，仅允许站内路径）
- `read_at`（可空）
- `created_at`、`updated_at`

通知查询始终使用当前认证用户的 `user_id` 过滤，并按创建时间倒序分页。标记已读时同时校验通知归属，不能通过修改 ID 读取或修改其他用户通知。

统一 API：

- `GET /api/v1/notifications`
- `GET /api/v1/notifications/unread-count`
- `PUT /api/v1/notifications/{id}/read`
- `PUT /api/v1/notifications/read-all`

创建通知使用服务接口，例如 `Notify(userID, NotificationInput)`。通知类型和正文由调用方提供，URL 仅接受应用内相对路径，禁止注入外部跳转地址。

## 前端设计

在 `admin/src/core/layouts/AdminShell.vue` 增加通用通知入口，数据请求和类型放入 `admin/src/core/notifications/`，不把通知逻辑散落到业务页面。

入口提供：

- 未读数量徽标
- 最近通知下拉列表
- 单条标记已读
- 全部标记已读
- 点击通知后跳转站内 URL
- 加载中、空状态、接口失败和中英文 i18n

通知入口不新增独立后台菜单，避免把基础能力误作为业务资源显示。

## 权限与安全

- 通知 API 需要登录。
- 用户只能访问自己的通知。
- 通知创建只能由后端业务服务调用。
- URL 只允许应用内相对路径，前端不直接打开外部地址。
- 通知正文按普通文本渲染，不允许直接注入 HTML。
- 通知列表不记录密码、令牌、Cookie 或其他敏感认证数据。

## 验收标准

1. 已登录用户可以看到自己的通知和未读数量。
2. 未读数量随单条或全部标记已读正确减少。
3. 用户无法通过 API 读取或修改其他用户通知。
4. 分页、空状态、失败状态和中英文显示正常。
5. 通知点击只允许站内跳转。
6. 后端服务、控制器、权限边界和前端核心组件有自动化测试。
7. 不新增第三方依赖，不引入邮件、短信、WebSocket、插件、文件上传或导入功能。
