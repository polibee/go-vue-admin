# Resource Generator Design

## 目标

为当前 Admin Resource Engine 增加第一个可复用的生成器切片：`admin:make-resource`。它根据显式的资源名、标签、路由和字段定义，生成一组可编译、可测试的后端 Resource 基础文件，并把生成结果与人工业务代码隔离，避免重复执行命令时覆盖人工修改。

本阶段只实现后端 Resource 生成基础，不实现前端页面生成、AI 建议、插件安装、数据库反向工程或完整 CRUD 业务逻辑。

## 约束与成功标准

- 生成器在 `backend/` 项目根目录通过 Artisan 命令执行。
- 输入必须显式提供资源名；字段使用重复的 `--field=name:type[:required]` 选项。
- 资源名使用小写字母、数字和单个连字符，且必须以字母开头；生成的 Go 标识符由资源名转换为 PascalCase。
- 支持的第一批字段类型为 `text`、`email`、`password`、`integer`、`boolean`、`select`。
- 相同输入必须产生字节稳定的输出，字段顺序按命令输入顺序保留。
- 所有生成文件必须写入生成器专用目录，不覆盖现有人工文件。
- 目标文件已存在时，命令默认失败并返回明确路径；本阶段不提供强制覆盖开关。
- 生成文件包含统一的 `Code generated by admin:make-resource. DO NOT EDIT.` 标记。
- 模板渲染失败、非法名称、重复字段名和不支持字段类型都必须在写文件前失败，不能留下半套输出。
- 不新增第三方依赖，不修改现有数据库迁移，不自动执行迁移。

## 命令契约

```text
go run . artisan admin:make-resource posts \
  --label="Posts" \
  --route="/admin/posts" \
  --permission="admin.posts.view" \
  --field=title:text:required \
  --field=published:boolean
```

必需参数：

- `name`：资源机器名。
- 至少一个 `--field`。

可选参数：

- `--label`：默认由资源名生成标题文本。
- `--route`：默认 `/admin/<name>`。
- `--permission`：默认 `admin.<name>.view`。

输出摘要必须列出生成文件；任何错误都使用非零退出码。

## 输出边界

生成器内部拆分为三个纯边界：

1. `Spec`：解析并验证命令输入，输出规范化资源定义。
2. `Renderer`：将 `Spec` 渲染成路径与内容的内存集合，负责模板和稳定格式。
3. `Writer`：在全部内容渲染成功后检查冲突，再以临时文件加原子重命名写入目标目录。

首个输出集合固定为：

```text
backend/app/generated/resources/<name>/manifest.go
backend/app/generated/resources/<name>/model.go
backend/app/generated/resources/<name>/request.go
backend/app/generated/resources/<name>/repository.go
backend/app/generated/resources/<name>/service.go
backend/app/generated/resources/<name>/controller.go
backend/app/generated/resources/<name>/routes.go
backend/app/generated/resources/<name>/permissions.go
backend/app/generated/resources/<name>/manifest_test.go
```

生成的 `manifest.go` 使用当前 `app/resource.Manifest`、`Field`、`Column` 和 `Option` 契约；其余文件提供明确的接口骨架并标注需要人工实现的业务边界，但不自动接入现有路由或 Resource Registry。接入动作必须由开发者审阅后手工完成，避免生成器替换平台级注册逻辑。

## 冲突与失败语义

- 命令启动时先解析、验证和完整渲染所有输出。
- 任一目标路径已经存在时，整个命令失败，不写入任何目标文件。
- 目标目录创建失败或写入失败时返回错误；临时文件在失败时清理。
- 生成器不得删除、修改或重命名用户现有文件。

## 测试策略

- 单元测试覆盖资源名规范化、字段解析、重复字段、非法类型、默认值和稳定排序。
- Golden File 测试以一个 `posts` 输入固定全部输出路径与内容。
- Writer 测试验证目标文件冲突时零写入，并验证成功时所有文件都存在。
- Artisan 命令测试验证错误返回非零以及成功输出文件摘要。
- 运行 `go test ./... -count=1`，并使用临时目录执行一次真实命令 smoke test。

## 后续扩展边界

后续可以在不改变 `Spec`、`Renderer`、`Writer` 接口的前提下增加 `admin:make-module`、`admin:make-crud`、前端页面和 OpenAPI 骨架。任何涉及现有业务文件自动合并、数据库反向推断或 AI 生成的能力都需要单独设计和验收。
